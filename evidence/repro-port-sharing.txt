Claim 1: cookies are not isolated by port (RFC 6265 section 8.5)
================================================================
  server A (port 37301) set:  app_session=SECRET-FROM-PORT-A  (host-only, no Domain)
  server B (port 37302) received Cookie: app_session=SECRET-FROM-PORT-A; wishful=parent-scope
  [CONFIRMED] A cookie set by one localhost port is sent to a different localhost port.
              Two unrelated apps on one machine share a single cookie jar. Ports are not a boundary.
  server A now receives Cookie: wishful=parent-scope; app_session=OVERWRITTEN-BY-PORT-B
  [CONFIRMED] A second app on another port can overwrite the first app's session cookie.
              Session fixation between unrelated local projects is one navigation away.

Claim 2b: Domain=.localhost set from localhost is stored host-only, not as a parent scope
=========================================================================================
  set from http://localhost:37301 :  wishful=parent-scope; Domain=.localhost
  stored as: domain="localhost"
  [CONFIRMED] It is accepted, but stored with domain "localhost" rather than ".localhost" -- i.e. host-only.
              The leading dot is stripped per RFC 6265 5.2.3, and a domain-attribute identical to the request host yields a host-only cookie.
  http://app.localhost:37303 received Cookie: (none)
  [CONFIRMED] That cookie does not reach app.localhost either.
              So neither direction works: there is no way to write a cookie that localhost and its subdomains share.
